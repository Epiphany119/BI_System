# 智能 BI 平台 V1.0

## 智能分析任务技术设计

| 项目 | 内容 |
|---|---|
| 对应 PRD | PRD-V1.0-创建智能分析任务 |
| 设计版本 | V1.0 |
| 状态 | 待评审 |
| 文件限制 | 单文件最大 5MB |
| 推荐执行模式 | 异步 |

## 1. 技术目标

- 将创建分析请求与耗时 AI 执行解耦。
- 使用任务状态机约束任务生命周期。
- 支持自动重试、手动重试、取消等待任务和结果版本。
- 保证重复提交、重复消息和消费者重启不会产生重复结果。
- 保持现有 Spring Boot、MySQL、Redis、RabbitMQ 和对象存储架构兼容。

## 2. 总体架构

```text
React 前端
   │ HTTP / SSE 或轮询
   ▼
ChartTaskController
   │ 鉴权、参数校验、限流
   ▼
ChartTaskService ─────── MySQL
   │                     ├─ chart_task
   │                     └─ chart_result
   │
   ├─ 文件保存 ───────── COS / 本地临时目录
   │
   └─ RabbitMQ
          ▼
   BiTaskConsumer
          │ 幂等检查、状态更新、重试
          ▼
      AiManager
          ▼
      结果持久化
```

同步模式复用任务服务和结果持久化逻辑，但在创建请求内执行；异步模式只在请求内创建任务并投递消息。

## 3. 数据库设计

### 3.1 chart_task

```sql
CREATE TABLE chart_task (
  id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  task_no VARCHAR(32) NOT NULL COMMENT '业务任务号',
  user_id BIGINT NOT NULL COMMENT '创建人',
  dataset_name VARCHAR(255) NOT NULL COMMENT '原始文件名',
  dataset_path VARCHAR(500) NOT NULL COMMENT '内部文件地址',
  dataset_size BIGINT NOT NULL COMMENT '文件字节数',
  goal VARCHAR(500) NOT NULL COMMENT '分析目标',
  chart_name VARCHAR(100) DEFAULT NULL COMMENT '图表名称',
  chart_type VARCHAR(30) DEFAULT NULL COMMENT '图表类型',
  mode VARCHAR(20) NOT NULL COMMENT 'SYNC/ASYNC',
  status VARCHAR(20) NOT NULL COMMENT 'WAITING/RUNNING/SUCCEEDED/FAILED/CANCELED',
  retry_count INT NOT NULL DEFAULT 0 COMMENT '重试次数',
  idempotency_key VARCHAR(64) NOT NULL COMMENT '幂等键',
  error_code VARCHAR(50) DEFAULT NULL COMMENT '错误码',
  error_message VARCHAR(1000) DEFAULT NULL COMMENT '脱敏后的错误信息',
  started_at DATETIME DEFAULT NULL,
  finished_at DATETIME DEFAULT NULL,
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_delete TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_task_no (task_no),
  UNIQUE KEY uk_user_idempotency (user_id, idempotency_key),
  KEY idx_user_status (user_id, status),
  KEY idx_create_time (create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='智能分析任务';
```

### 3.2 chart_result

```sql
CREATE TABLE chart_result (
  id BIGINT NOT NULL AUTO_INCREMENT,
  task_id BIGINT NOT NULL,
  result_version INT NOT NULL DEFAULT 1,
  gen_chart LONGTEXT NOT NULL COMMENT 'ECharts JSON',
  gen_result TEXT NOT NULL COMMENT '分析结论',
  raw_response TEXT DEFAULT NULL COMMENT '脱敏后的模型原始响应',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_task_version (task_id, result_version),
  KEY idx_task_id (task_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='智能分析结果';
```

结果表不直接覆盖历史结果。重试成功时，新建 `result_version = max(version) + 1`。

## 4. 状态机实现

状态常量：

```java
public enum ChartTaskStatus {
    WAITING, RUNNING, SUCCEEDED, FAILED, CANCELED
}
```

允许的状态转换：

```text
WAITING  -> RUNNING
WAITING  -> CANCELED
WAITING  -> FAILED
RUNNING  -> SUCCEEDED
RUNNING  -> WAITING   // 可重试异常
RUNNING  -> FAILED    // 不可重试或超过重试次数
RUNNING  -> CANCELED  // 仅实现可取消时允许
FAILED   -> WAITING    // 手动重试
```

所有更新必须使用带旧状态条件的 SQL，例如：

```sql
UPDATE chart_task
SET status = 'RUNNING', started_at = NOW()
WHERE task_no = ? AND status = 'WAITING' AND is_delete = 0;
```

受影响行数为 0 时，表示任务已被其他消费者处理或已进入终态，当前消息应安全结束。

## 5. 接口设计

### 5.1 创建任务

`POST /api/chart/task`

请求类型：`multipart/form-data`

```text
file: MultipartFile
goal: String
name: String?
chartType: String?
mode: SYNC | ASYNC
idempotencyKey: String
```

校验：

- 登录用户必填。
- 文件非空，后缀仅允许 csv、xlsx。
- 文件大小不超过 5 * 1024 * 1024 字节。
- `goal` 长度 5-500。
- `name` 长度不超过 100。
- 同一用户并发 WAITING/RUNNING 任务不超过 3 个。
- 同一用户相同幂等键直接返回已有任务。

### 5.2 查询任务

`GET /api/chart/task/{taskNo}`

返回：

```json
{
  "code": 0,
  "data": {
    "taskNo": "AT202609200001",
    "status": "SUCCEEDED",
    "retryCount": 0,
    "resultVersion": 1,
    "genChart": "{...}",
    "genResult": "...",
    "errorMessage": null,
    "createdAt": "2026-09-20T12:00:00+08:00",
    "finishedAt": "2026-09-20T12:00:18+08:00"
  }
}
```

### 5.3 任务列表

`POST /api/chart/task/list/page`

查询条件：状态、模式、任务名称、创建时间范围；每页最多 20 条，只返回当前用户任务，管理员可增加用户条件。

### 5.4 取消任务

`POST /api/chart/task/{taskNo}/cancel`

采用状态条件更新。只有 WAITING 任务可以稳定取消；RUNNING 任务若已进入 AI 调用，接口返回不可取消，不强行中断线程。

### 5.5 重试任务

`POST /api/chart/task/{taskNo}/retry`

仅 FAILED 可重试；创建新的待执行消息，但复用原始文件和分析参数。达到最大重试次数后返回业务错误。

### 5.6 删除任务

`DELETE /api/chart/task/{taskNo}`

执行逻辑删除。删除前校验用户归属；SUCCEEDED 任务的结果按照保留策略处理，默认保留 30 天后清理。

## 6. RabbitMQ 设计

### 6.1 交换机和队列

| 类型 | 名称 |
|---|---|
| Exchange | `bi.chart.task.exchange` |
| Routing Key | `bi.chart.task.execute` |
| Queue | `bi.chart.task.queue` |
| Dead Letter Queue | `bi.chart.task.dlq` |

### 6.2 消息体

```json
{
  "taskId": 10001,
  "taskNo": "AT202609200001",
  "userId": 20001,
  "attempt": 1,
  "traceId": "trace-uuid"
}
```

消息不携带原始文件内容和密钥，只携带任务 ID。消费者从数据库读取任务参数和文件地址。

### 6.3 消费流程

1. 根据 `taskId` 查询任务。
2. 如果任务不存在、已删除或处于终态，确认消息并结束。
3. 使用条件更新将 WAITING 改为 RUNNING。
4. 调用文件解析和 AI 服务。
5. 成功时事务内写入 `chart_result`，并将任务改为 SUCCEEDED。
6. 可重试异常时增加 retry_count，任务回到 WAITING，发送延迟消息。
7. 不可重试异常时写入错误码和错误信息，任务改为 FAILED。

## 7. 重试与错误分类

可重试：

- AI 服务连接超时。
- AI 服务 429 或临时 5xx。
- RabbitMQ 消费过程中的临时网络异常。

不可重试：

- 文件格式错误。
- 文件内容无法解析。
- 分析目标非法。
- AI 返回无法修复的结构化格式错误。
- 用户权限异常。

默认策略：最多自动重试 3 次，延迟 5 秒、30 秒、120 秒；用户手动重试重新进入 WAITING，但总重试次数不能超过系统上限。

## 8. 幂等与一致性

- 创建接口通过 `(user_id, idempotency_key)` 唯一索引保证幂等。
- 消费者通过 `WAITING -> RUNNING` 条件更新抢占任务。
- 结果通过 `(task_id, result_version)` 唯一索引防止重复写入。
- 任务状态和结果写入使用同一事务。
- 数据库事务提交后再确认 RabbitMQ 消息，避免结果未落库时丢失消息。
- 消费者异常退出时，RabbitMQ 重新投递未确认消息。

## 9. 安全设计

- 所有任务接口必须登录。
- 所有任务查询必须校验 `task.user_id == loginUser.id` 或管理员角色。
- 文件名只用于展示，文件存储路径使用随机任务目录，禁止拼接用户输入路径。
- 服务端重新校验 MIME、后缀和文件大小，不能只信任前端。
- 日志禁止记录文件内容、密码、AccessKey 和完整模型请求。
- AI 返回内容前端按纯文本展示，避免 XSS。
- 结果下载需要再次校验任务权限和有效期。

## 10. 可观测性

日志字段至少包含：`traceId`、`taskNo`、`userId`、`status`、`attempt`、`durationMs`、`errorCode`。

指标建议：

- `chart_task_created_total`
- `chart_task_succeeded_total`
- `chart_task_failed_total`
- `chart_task_retry_total`
- `chart_task_duration_ms`
- `chart_ai_timeout_total`
- `chart_task_queue_depth`

管理员后续可在任务中心查看成功率、平均耗时、失败原因 Top N 和队列堆积情况。

## 11. 测试设计

### 单元测试

- 参数校验器：文件大小、后缀、文本长度。
- 状态机：合法和非法状态转换。
- 重试策略：次数、延迟和错误分类。
- 幂等服务：重复幂等键返回同一任务。

### 集成测试

- MySQL 任务创建和唯一索引。
- RabbitMQ 投递、消费和重复消息。
- AI 成功、超时、429、5xx 和格式错误。
- 任务取消与并发状态更新。

### 接口验收

- 未登录返回 401。
- 越权查询返回 403 且不泄露任务信息。
- 超过 5MB 文件返回参数错误。
- 失败任务可以手动重试。
- 成功任务返回图表和结论。

## 12. 上线与回滚

上线顺序：

1. 执行新增表结构和索引。
2. 发布后端任务接口和消费者。
3. 配置 RabbitMQ 交换机、队列和死信队列。
4. 发布前端任务创建和详情页面。
5. 开启灰度用户并观察任务成功率。

回滚策略：

- 前端可以回退到旧的 `/api/chart/gen` 接口。
- 新表保留，不立即删除，避免影响任务数据。
- 停止消费者前先暂停新任务入口，等待 RUNNING 任务完成或进入重试。
